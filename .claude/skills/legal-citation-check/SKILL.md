# 법령 인용 검증 (legal-citation-check)

## 목적

법률 연구보고서에서 환각은 **검증 루프가 없는 출처에 집중된다.** 법령·판례는
API라는 외부 그라운드 트루스에 묶여 있어 안전하지만, 폴더 내 문서(법령안
심사기준 등)는 한 번 읽고 나면 모델의 기억에 의존하게 되어 "문서에 없는
내용을 그 문서 출처로 인용"하는 환각이 발생한다. 이 스킬은 모든 인용 종류에
명시적 검증 절차를 강제해 이를 차단한다.

핵심 원칙:
- 검증되지 않은 인용은 보고서에 넣지 않는다.
- 확인할 수 없으면 지어내지 말고 "[미검증]" 또는 "명시 없음"으로 표기한다.
- 인용은 본문 작성 후 붙이는 장식이 아니라, 검증을 통과해야 생성된다.

---

## A. 법령·조례(자치법규) 인용 — API 2회 검증

법률, 시행령, 시행규칙뿐 아니라 **조례·규칙 등 자치법규도 동일하게** 처리한다.

### 1차 검증 — 인용을 작성하는 시점
- 인용하려는 법령·조례를 설정된 법령 API로 직접 조회한다.
  (자치법규는 자치법규 검색 경로를 사용한다. 법령 검색에 안 나온다고
  "조례 없음"으로 단정하지 말 것.)
- 다음을 모두 확인한다:
  - 정확한 법령명/조례명 (소관 지자체명 포함)
  - 조·항·호·목 번호
  - 인용할 조문의 **원문 텍스트**
  - 시행일자 / 현행 여부 (개정·폐지 여부 확인)
- 보고서에는 API에서 확인한 원문 그대로의 표현을 사용한다.

### 2차 검증 — 초안 완성 시점
- 초안이 완성되면, 본문에 등장하는 **모든 법령·조례 인용을 다시 한 번
  API로 재조회**한다.
- 재검증 시 확인 항목:
  - 인용된 조문 번호가 실제 존재하는가
  - 인용된 조문 텍스트가 API 원문과 일치하는가 (작성 중 표현이
    미끄러지지 않았는가)
  - 시행일/현행 여부가 보고서 기준 시점과 맞는가
- 불일치하거나 조회되지 않으면: 해당 인용을 수정하거나 삭제하고,
  사용자에게 어떤 인용이 왜 검증에 실패했는지 보고한다.

### 금지
- API로 확인하지 않은 법령·조례를 기억에 의존해 인용 금지.
- 조문 번호·문구를 추정하거나 "보통 이런 조항이 있다"는 식으로 작성 금지.

---

## B. 판례 인용 — API 검증

- 인용하려는 판례를 설정된 판례 API로 직접 조회한다.
- 사건번호, 선고일자, 법원, 판시사항·판결요지 원문을 확인한다.
- 판시 내용을 요약·바꿔쓸 때도 원문 의미에서 벗어나지 않게 하고,
  핵심 법리는 가능한 한 원문 문구를 인용한다.
- 조회되지 않는 사건번호는 인용하지 않는다. 추정 사건번호 생성 금지.

---

## C. 법령안 심사기준 등 폴더 내 문서 — 원문 grep 대조

법제처 「법령 입안·심사 기준」 같은 문서는 API가 없으므로, **파일 자체를
그라운드 트루스로 삼는 검증 절차**를 적용한다.

### 인용 작성 규칙
1. 인용 시 파일에서 따온 **원문 문구를 큰따옴표로 그대로** 넣고,
   페이지/항목 번호를 표기한다. 요약·바꿔쓰기로 인용하지 말 것.
2. 파일에 없는 내용을 일반 지식(학습된 사전지식)으로 보충하지 말 것.
   해당 기준이 없으면 "심사기준에 명시 없음"으로 적는다.
3. 큰 파일/PDF는 전체를 읽었는지 먼저 확인하고, 읽지 않은 부분은
   인용하지 않는다. 스캔본 PDF로 본문 추출이 불완전하면 사용자에게
   텍스트본 교체를 요청한다.

### 초안 완성 시점 검증 패스
- 본문의 모든 심사기준 인용에 대해, 인용한 원문 문구를 해당 파일에서
  `grep`(또는 Read)으로 재검색해 **실제 존재 여부를 확인**한다.
- 파일에서 찾지 못한 인용은 삭제하거나 "[미검증]"으로 표기하고,
  사용자에게 보고한다.

---

## D. 작성 후 최종 검증 체크리스트

초안 완성 후 다음을 모두 수행하고, 결과를 사용자에게 요약 보고한다.

- [ ] 모든 법령·조례 인용을 API로 2차 재조회했는가
- [ ] 인용 조문 번호·문구가 API 원문과 일치하는가
- [ ] 시행일/현행 여부가 보고서 기준 시점과 맞는가
- [ ] 모든 판례 인용의 사건번호를 API로 확인했는가
- [ ] 모든 심사기준 인용 문구를 원본 파일에서 grep으로 확인했는가
- [ ] 검증 실패·미확인 인용을 "[미검증]"으로 표기하고 별도로 보고했는가

검증을 통과하지 못한 인용이 하나라도 있으면, 보고서를 "완료"로
보고하지 말고 어떤 인용이 왜 실패했는지 명시한다.

---

## 출력 규칙

- 보고서 끝에 "인용 검증 결과" 절을 두어, 각 인용의 검증 상태
  (API 확인 / 파일 확인 / 미검증)를 표로 정리한다.
- 미검증 항목은 빠뜨리지 말고 명시적으로 나열한다.
